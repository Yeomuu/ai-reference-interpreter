# 너비·진행 표시 수정 및 기능 회귀 검사 · 2026-10-06

## 수정 범위

- 헤더와 메인 콘텐츠를 최대 1368px·공통 좌우 여백(36/24/16px)으로 연결했다.
- 진행 표시의 원은 기본 24px, 낮은 창은 20px, 내부 아이콘은 12px로 축소했다. 단계명은 기존 12px, 줄 높이는 16px이며 최소 48px 조작 영역을 유지한다. 내용 중앙 정렬로 헤더 상하 여백을 확보했다.
- 변경은 tokens.css/app.css/layout-mapping.css와 사양·QA 문서다. 기능·데이터·서버 코드는 변경하지 않았다.

## 실행 환경과 결과

사용자 자료와 분리된 headless Chrome을 사용했다. 각 기능 검사는 별도의 브라우저 저장소에서 실행했다. 유료 이미지 호출은 0회다. AI 요청의 모의 응답은 요청 구성·저장·결과 수정만 확인하며 실제 모델 품질의 증거가 아니다. AURA 예시의 사전 제공 샘플은 실제 파일을 열고 다운로드했다.

## 화면 경계와 진행 표시

- 목록 11개 폭 및 7개 프로젝트 URL × 9개 데스크톱 폭, 총 74개 조합에서 헤더/콘텐츠 left·right·width가 일치했다. 최대 1368px, 기존 헤더 반응형 여백, 문서 가로 넘침 없음, 저장 구조·배치 유지와 도구 접근을 확인했다.
- 1920×1080 / 1575×884 / 1440×900 / 1280×720 / 1101×884 / 1070×671 / 사용자 주석의 614×672에서 네 단계, 총 28개 상태의 진행 표시를 확인했다. 현재 원의 외곽선 위 여백은 최소 4px, 단계명 아래 여백은 최소 8px이며 버튼은 최소 48px 높이다.
- 1440px·614px 캡처를 직접 확인했다. 진행 표시의 위치, 클릭·Enter·뒤로/앞으로·reload와 현재 단계 표시를 유지한다. 기능 검사 중 JavaScript 오류는 없었다.

## 남은 범위와 제한

- 1070px 이상 데스크톱 검사 범위에서 새 기능 차단 오류를 발견하지 않았다.
- 기존 614px 좁은 창에서는 고정 폭 3열 편집 패널 때문에 도면이 작아지고 헤더의 단계명이 겹치거나 가이드가 잘릴 수 있다. 이번 주석의 세로 여백은 수정했으며, 전체 모바일/좁은 창 편집 구조는 변경하지 않았다. 현재 논문 작업 환경은 1070px 이상 데스크톱을 기준으로 확인했다.
- 기존 JS 묶음 607.02kB의 >500kB 빌드 경고는 남는다. 빌드는 성공한다.
- 실제 유료 모델의 생성 품질·공간 일치, 공식 인체치수에 대한 눈높이 임시값의 타당성은 이번 기능 회귀 검사로 검증하지 않는다.

사용자가 두 변경의 GitHub 반영을 승인했다. 배포 후 공개 도메인에서도 너비·진행 표시와 기능 회귀를 확인한다.
