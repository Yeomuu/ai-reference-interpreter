# 현재 로직 QA 및 최종 변경 기록 · 2026-10-08

사용자 요청에 따라 디자인 변경 후 기술적 로직을 점검했다. 기존 기능을 재작성하지 않고 재현된 문제를 수정했다. 전체 기능 설명: [CURRENT_LOGIC_20261008.md](CURRENT_LOGIC_20261008.md).

## 실제로 발견하고 수정한 문제

| 문제 | 재현·원인 | 수정·검증 |
|---|---|---|
| 이미지 연결 해제/삭제 후 생성 불가 | 벽/공간의 `mapping-condition`이 빈 sourceReferenceId로 남음. 새 테스트 2개를 수정 전에 실행해 실패 재현 | 파생 조건만 제거. 독립 배치·상품 받침·원래 구조·과거 스냅샷 유지. 테스트와 실제 UI 통과 |
| 도면 없는 2단계에서 이동 버튼 누락 | 페이지 전체가 Empty로 조기 반환, 기존 외부 footer 제거 후 대체 없음 | 빈 도면 안내와 오른쪽 준비 패널 내부 footer/설정 복귀 버튼. 직접 캡처에서 패널 폭 문제도 확인·수정 |
| 도면 교체의 ‘기존 표시 유지’ 선택 누락 | 처리 로직은 있으나 최신 일반 공간 설정에서 select 미표시 | 평면도 탭의 접힌 교체 옵션 복구. fresh/retain·실제 비율·대응 확인·Undo/reload 검사 |
| 고정 벽의 속성 선택 불가 | 일반 선택도 onWallSelect 경로로 들어가고 장식 도구가 없으면 아무 동작도 하지 않음 | 일반 선택은 구조 속성으로 연결. 필수 보존 스위치 비활성, 구조 데이터 유지 검사 |
| 삭제 복구가 새로고침 후 사라짐 | undoAction과 일반 편집 스택이 메모리에만 있음 | 마지막 삭제 patch를 별도 저장. 개정 일치·스키마/복구 데이터 검증, 저장 실패 롤백, 도면 Undo/키보드 연결. 새 단위 테스트 8개 및 실제 reload 후 알림 종료/Ctrl+Z 통과 |
| 알림이 하단 단계 이동을 가림 | 데스크톱 알림 bottom이 외부 footer 시절 기준 | 기존 navigation 높이 토큰으로 footer 위에 표시. 알림 하단/패널 footer 좌표 비겹침 검사 |

QA 스크립트의 예전 홈 진입 selector와 진행 문구 `04`/`04.` 차이를 최신 UI에 맞췄다. 상품 테스트는 둥근 footprint의 투명 모서리를 클릭하던 지점을 실제 그려진 상단 가장자리로 수정했다. force click이나 인위적인 DOM 이벤트로 기능 성공을 가장하지 않았다.

API 테스트의 quota 장애/공급자 오류 stderr는 의도적으로 주입한 실패 케이스이며 전체 테스트 결과는 통과다. 브라우저 검사는 격리 프로필을 사용해 사용자의 현재 프로젝트를 편집하지 않았다. 스크립트들에서 JavaScript pageerror가 없음을 확인했다.

모든 브라우저 생성 요청은 `/api/generate` 모의 응답 또는 차단이다. current-logic의 두 POST는 성공 JPEG 1개 + 두 번째 불확실 오류의 모의 시나리오다. 스크린샷의 ‘AI 생성’ 표시는 이 격리된 mock UI를 검사한 것으로, 실제 모델 실행의 증거가 아니다. 이 QA의 유료 모델 호출은 0회다.

## 남은 한계와 검증하지 않은 것

- Vite가 500kB 초과 단일 JavaScript 묶음 경고를 표시한다(최종 JS 약 652kB, gzip 약 197kB). 빌드 실패는 아니지만 분할/성능 개선은 이번 요청에서 추가로 재작성하지 않았다.
- 실제 Vercel 배포 완료와 live Blob 동시 경쟁/한도 차감, 실제 유료 모델 품질은 이번 QA에서 실행하지 않았다. production 검사는 로컬 dist preview다.
- 실제 iOS Safari/Android 기기 및 스크린 리더 인증을 하지 않았다. 격리 Edge/Chromium의 실제 화면·키보드·반응형 검사다.
- 코드의 2D 점유/보존 규칙을 검사했다. 실제 측량/시공/고정 방식/적재·광학/모델 공간 정확도를 검증한 것으로 해석하지 않는다.
- 일반 50개 편집 스택 전체는 새로고침 후 보관되지 않는다. 마지막 삭제 복구는 별도 저장되며 후속 commonRevision 변경 뒤에는 오래된 patch를 적용하지 않는다.

커밋·원격 푸시 완료 여부와 SHA는 최종 사용자 보고 및 Git 원격 조회로 확인한다. 실제 배포 성공으로 확대 보고하지 않는다.
