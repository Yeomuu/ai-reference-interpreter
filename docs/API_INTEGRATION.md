# OpenAI 이미지 생성 연결

확인일: 2026-09-28. 아래 가격과 모델 지원 범위는 배포 후에도 [OpenAI 공식 모델·요금 안내](https://developers.openai.com/api/docs/models/gpt-image-1-mini)에서 다시 확인해야 한다.

## 동작 범위

- 무료 탐색, 도면 편집, 조건 검토, 사전 제공 샘플은 API를 호출하지 않는다.
- 사용자가 조건 검토에서 명시적으로 **AI 이미지 생성**을 실행할 때만 `POST /api/generate`가 호출된다. `GET /api/status`는 서버 설정 유무만 확인하며 생성 또는 과금을 하지 않는다.
- 서버는 Vercel env의 `OPENAI_API_KEY`를 읽으며 브라우저에 보내지 않는다. 사용자 키·접근 코드 입력·참여 링크 없이 생성 버튼을 누른다. 잘못된 도면·배치·시점, 빠진 레퍼런스, 큰 입력은 호출 횟수 예약과 OpenAI 호출 전에 거절한다.
- 사용자가 선택한 기존 공간 사진 1장, 업로드 도면 이미지가 있으면 그 1장, 적용된 레퍼런스는 개수 제한 없이 포함한다. 3개 이하는 각각 보내고 더 많으면 번호가 붙은 최대 3개 이미지 모음으로 준비해 출처·선택 영역 목록과 함께 보낸다. 모음을 만드는 데 모델을 추가 호출하지 않는다. 샘플 개략 도면은 사진에서 추론한 측량 도면으로 취급하지 않으며, 구조·배치·시점의 정규화 좌표를 문장 조건으로 전달한다. 실제 AI 결과에는 어떤 기존 사진을 입력했는지 기록한다.
- 브라우저는 전송 전 이미지를 JPEG로 축소한다. 레퍼런스의 적용 요소가 모두 부분 영역을 가리키면 원본의 해당 픽셀을 잘라 보낸다. 한 원본에서 서로 다른 부분 영역이 2~4개면 한 장의 격자 이미지에 합치고, 생성 지시문은 각 칸의 출처를 구분한다. 같은 원본의 적용 요소 중 전체 이미지를 참조하는 요소가 있으면 원본 전체를 보낸다. 서로 다른 부분 영역 5개 이상은 유료 요청 전에 거절한다. 서버는 이 준비 정보와 프로젝트의 저장 조건이 일치하는지 검증한다.
- 서버는 최대 5장, 장당 550 KB, 요청 본문 4 MB를 제한한다. 서버는 프로젝트와 배치 조건을 재검증한다.
- `vercel.json`은 생성 함수에 최대 180초를 배정한다. [Vercel 함수 실행 시간 안내](https://vercel.com/docs/functions/configuring-functions/duration)에 따르면 Hobby의 Fluid Compute가 켜진 경우 300초까지 가능하지만, 꺼진 Hobby 환경은 최대 60초이므로 배포 설정을 확인해야 한다. 요청·응답의 [4.5 MB 제한](https://vercel.com/docs/errors/function_response_payload_too_large) 때문에 입력 이미지와 결과 JPEG 크기를 제한한다.
- 생성 결과는 브라우저 IndexedDB에 저장하고 프로젝트 기록에는 `asset://` URI와 `origin: 'ai'`를 보관한다. 과거 결과를 덮어쓰지 않는다. 생성 응답을 확인했지만 프로젝트 기록 저장이 실패하면 현재 탭의 메모리에 결과를 표시하고 즉시 이미지 내보내기와 기록 저장 재시도를 제공한다. 저장 문제를 해결하기 전에는 추가 유료 요청을 막는다.
- 전송 뒤 네트워크가 끊기거나 성공 응답을 읽지 못하면 서버 작업과 과금 여부를 단정할 수 없다. 같은 페이지 세션에서 180초 동안 재시도를 막고, 이후에도 사용자가 결과 이력·사용량을 확인한 뒤 명시적으로 잠금을 풀어야 한다. 이 보호와 별도로 서버의 공유 저장소가 요청 UUID 재전송, 동시에 진행 중인 요청, 전체/하루 호출 상한을 검사한다. 이미 예약한 요청은 실패하거나 결과가 불확실해도 횟수를 반환하지 않는다.

## 모델과 비용

현재 서버 설정은 `gpt-image-1-mini`, `quality=low`, `size=1536x1024`, `n=1`, `input_fidelity=low`, JPEG 출력이다. OpenAI의 [GPT-Image-1 Mini 공식 가격 표](https://developers.openai.com/api/docs/models/gpt-image-1-mini)는 낮은 품질의 1536×1024 출력 1장에 **$0.006** 예시를 제시한다. 이는 총 청구액이 아니다. 입력 문장은 $2/백만 토큰, 입력 이미지는 $2.50/백만 토큰의 별도 요금이 있으며 실제 비용은 입력 내용과 청구 시점 가격에 따라 달라진다. 모델 페이지는 무료 사용 등급에서 이미지 생성을 지원하지 않는다고 명시하므로, 프로젝트 결제 설정과 사용 한도도 별도로 확인해야 한다.

이 모델은 [OpenAI 공식 사용 종료 공지](https://developers.openai.com/api/docs/deprecations)에 따라 **2026-12-01 API 종료 예정**이다. 초기 비용 최소화를 위한 한시적인 선택이며, 그 전에 `gpt-image-2` 같은 지원 모델로 교체해야 한다. `gpt-image-2`는 낮은 품질의 가로 출력 예시가 $0.005이지만 입력 이미지 토큰은 $4/백만 토큰이고 입력 충실도를 낮출 수 없어, 여러 레퍼런스를 보내는 이 흐름의 총액이 반드시 더 저렴하다고 단정할 수 없다. 모델 이름·품질·크기 값은 공용 계약 파일 한곳에 모아 교체하도록 했다.

[공식 이미지 생성 안내](https://developers.openai.com/api/docs/guides/image-generation)는 이미지 편집 API가 여러 참조 사진을 입력받고 JPEG 출력을 지원한다고 설명한다. 같은 안내는 구조화된 구도에서 정확한 위치 재현에 한계가 있음을 명시한다. 따라서 이 서비스의 Keep·도면 검증은 생성 **전 입력 검증**이며, 생성 이미지가 그 제약을 완벽히 지켰다는 자동 판정이 아니다. 사용자가 결과를 직접 검토하고 승인해야 한다.

## 배포 설정과 검증 상태

서버 env `OPENAI_API_KEY`와 비공개 Vercel Blob 인증이 필요하다. 2026-09-28 서울 리전의 `ai-reference-generation-quota`를 이 프로젝트 Production/Preview에 연결했고, `generation-quota/v1.json`을 전체 60회·하루 20회·사용 0회로 최초 초기화했다(당시 계약). 2026-09-29 사용자 요청으로 전체 하루 60회·익명 브라우저 하루 20회로 갱신하며 기존 경로와 기록을 보존한다. 두 배포 환경은 같은 횟수를 공유한다. 서버는 최신 원본을 읽고 ETag 조건부 쓰기로 예약에 성공한 한 요청만 모델을 호출한다. 같은 UUID는 완료 후에도 재실행하지 않는다. 동시에 한 요청만 처리하며 중단되면 240초 뒤 진행 중 잠금이 만료된다. 배포/오류/새로고침은 횟수를 초기화하지 않는다. 한국 시간 자정에만 서비스 전체·브라우저별 일일 한도가 갱신된다. 이전 요청 UUID의 비공개 불변 기록은 계속 남아 날짜가 바뀌어도 재실행을 거절한다. 공개 초기화 API는 없고 저장소가 없거나 손상/연결 실패하면 생성을 차단한다. 예약 기록에는 요청 UUID·시각·날짜·해시된 익명 브라우저 식별만 있고 사진·프로젝트·실험 로그는 없다.

운영자는 저장소를 삭제/초기화하지 말아야 한다. 일일 상한 증액·수동 초기화는 별도의 명시적 비용 결정과 코드/비공개 기록 관리가 필요하다. 60회는 비용이 달라지는 입력을 포함한 **횟수 상한**이며 달러 청구액 상한으로 보장하지 않는다. 다른 서비스/키로 실행한 호출은 이 서비스 상한에 포함되지 않는다. Vercel Blob의 [일관된 읽기·조건부 쓰기 공식 계약](https://vercel.com/docs/vercel-blob/using-blob-sdk)을 사용한다. [Hobby 포함 사용량](https://vercel.com/docs/vercel-blob/usage-and-pricing) 안에서는 저장소 무료이며 소진 시 서비스 자체가 제한된다. 별도 유료 저장소 플랜을 구매하지 않았다.

2026-09-27 노출된 키는 사용자가 폐기했다. 2026-09-28 새 키가 로컬/Vercel 서버 env에 저장돼 있으며 생성 당시 **7일 만료**를 선택했다. 이 상태 조회는 키의 존재와 저장소 접근을 확인하며, OpenAI 키 만료·결제·조직 인증을 유료 모델 요청 없이 검증하지 않는다. 이전 `GENERATION_ACCESS_CODE`는 사용하지 않는다.

배포 후 상태·직접 경로·입력 거절·카운터 유지 검증 결과는 `QA_KEEP_ROUTING_LOGS_20260928.md`에 기록한다. 실제 이미지 생성 성공을 대신하는 확인은 아니다.

타입 검사, 린트, 단위 테스트, 빌드는 유료 모델 호출 없이 수행한다. 라이브 OpenAI 이미지 편집 요청은 별도 유료 확인 전에는 실행하지 않았으므로, 실제 계정 결제·조직 인증·모델 접근 권한까지 성공했다고 주장하지 않는다. 계정 설정 문제나 API 실패 시 기존 결과와 무료 샘플은 유지된다.

## 2026-09-29 익명 브라우저·여러 시점
상태 GET은 서명된 익명 브라우저 쿠키를 발급/검증하며 읽기만 한다. 키·접근 코드·로그인 입력은 없다. 같은 브라우저 기준 하루 20회, Production/Preview 전체 합계 하루 60회, 한국 시간 자정에 갱신한다. 다른 브라우저/기기·쿠키 삭제를 통한 동일인 구별은 하지 못한다. 전역 한도는 유지된다. `GENERATION_IDENTITY_SECRET`를 별도로 두면 API 키 교체와 무관하게 서명 식별을 유지할 수 있고, 없으면 기존 서버 키를 서명에 사용한다. 비밀 값은 클라이언트/문서/실험 ZIP에 넣지 않는다.

여러 시점은 실제 이미지 1장마다 예약·모델 요청 1번으로 처리한다. 한 번에 선택한 수를 미리 확인하고 전체 처리 중 생성 버튼을 잠근다. 각 결과를 즉시 보관하고 후속 오류 시 남은 시점을 중단한다. 사전 검사 이후 다른 사용자 요청으로 공유 한도가 줄면 일부만 성공할 수 있으며 자동 재호출하지 않는다. 이 QA에서는 모든 이미지 POST를 모의 응답으로 대체했다. 상태 조회 성공은 실제 OpenAI 이미지 생성 성공이나 결제·조직 권한 확인을 의미하지 않는다.

첫 결과 이후 다음 요청이 이전 잠금에 막히지 않도록 서버는 이미지 응답 전에 완료 쓰기를 기다린다. 완료 쓰기는 최대 8초/함수 남은 시간 이내로 제한하고 모델 요청 제한도 응답 여유를 남긴다. 저장소 오류/지연 시 이미 받은 이미지는 전달하되 예약/미해제 잠금을 유지한다. 브라우저는 다음 시점 전 GET으로 준비 여부를 검사하고 처리 중이면 2초 간격으로 최대 20초 대기한다. 각 GET에도 제한 시간이 있다. 준비 여부/횟수를 확인할 수 없으면 남은 시점을 중단한다. 이는 무료 상태 확인이며 유료 요청 재시도나 quota 초기화가 아니다. 검증은 `QA_MULTI_VIEW_QUEUE_20260929.md`에 기록한다.

## 저장 배치 가이드와 조명 범위 · 2026-09-29
개략 도면에서도 저장 구조·배치·단일 카메라를 로컬 렌더링한 JPEG 가이드를 두 번째 이미지로 전송한다. 업로드 도면은 해당 가이드 배경에 포함되므로 이미지 슬롯을 추가로 소비하지 않는다. 참고 이미지가 많으면 기존 모음 방식으로 전달한다. 모델/low 품질/n=1/입력 충실도/서버 한도는 유지한다. 개략 도면에도 입력 이미지 한 장이 추가되어 입력 토큰 비용이 증가할 수 있으므로 총액이 기존과 같다고 단정하지 않는다.
가이드 위치가 영감 이미지의 공간 구성보다 우선하도록 요청하고, 선택 시점 기준 앞/뒤/좌/우를 평면 비율로 설명한다. 조명은 빛의 특성만, 객체는 해당 물체만, 색/재질은 별도 저장 요소의 대상만 전이한다. 이 요청은 결과의 완전한 구조 일치 보장이 아니다.
근거: [OpenAI 이미지 생성 공식 안내](https://developers.openai.com/api/docs/guides/image-generation), [이미지 프롬프팅 공식 안내](https://developers.openai.com/api/docs/guides/image-prompting)는 명확한 입력 역할/유지할 조건 설명과 실제 구도의 한계를 다룬다. [ERCO 상품 조명 안내](https://www.erco.com/en/designing-with-light/shop/presenting-6535/)는 진열 상품의 형태/색·재료 식별과 테이블 강조 조명을 설명한다. 이를 기반으로 빛과 재질 전이를 분리한 것은 이 서비스의 구현 판단이며 조명 설계 계산/자동 시공 검증이 아니다.

실제 샘플 1장 점검에서 전체 온색과 벽 그래픽의 벽면 불명확성이 남아, 중립 일반광/노출과 국소 온백색 빛을 분리하고 진열대의 바닥 대비 비율, 벽면의 시선 대비 방향, 같은 벽의 창/출입구 span을 추가 설명한다. 이는 렌더링 지시의 보강이며 실제 시공 치수 추정이나 완전한 위치 일치 판정이 아니다.
