## 발견한 남은 문제

- 데스크톱 폭에서 `07 결과`를 열어 둔 채 브라우저를 390px로 줄이면 가로 단계 탐색이 초기 위치에 남아 현재 단계가 화면 밖에 있다. 390px에서 단계를 직접 누르면 현재 단계로 이동한다. `App.tsx`의 단계 탐색 스크롤 처리를 뷰포트 폭 변경에도 적용해야 한다. 해당 파일은 API 작업과 충돌하지 않도록 이 점검에서 수정하지 않았다. [`10-results-390.png`](qa-evidence/ui-audit-20260927/10-results-390.png)
- 현재 검토 우측 요약은 길어서 실행 버튼이 1440×900 첫 화면보다 아래에 있다. 실행을 위한 무리한 고정 버튼보다, 실제 생성 비용·샘플 구분과 실행 결과를 버튼 바로 앞에 알리는 편이 적합하다. API UI 담당자에게 전달했다.

## 이번 수정과 확인

- `src/styles/app.css`에서 작업 도면의 최소 높이를 320→300px로 줄였다. 1280×800에서 도면 전체 조작면이 하단 바 위에 남는다.
- 767px 이하에서 목록·속성·요소·결과·구조 편집의 내부 최대 높이와 중첩 세로 스크롤을 해제했다. 도면 아래의 중복 보조 도움말만 숨겼고, 도면 자체의 조작 설명과 범례는 유지했다.
- 수정 후 390px에서 목록과 속성이 자연스러운 문서 스크롤로 이어지고 가로 본문 넘침은 없음을 확인했다. 768px에서 도면은 양쪽 패널보다 위의 전체 폭 행을 차지한다.
