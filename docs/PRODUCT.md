## 원본 화면과 보조 안내 · 2026-10-08 (최신)

홈/STEP 01은 사용자 원본 Figma의 구성·문구·타이포·SVG·컴포넌트 상태를 따른다. 이전의 STEP 02/03 R0 표현은 폐기하고 모든 외곽 편집 패널을 STEP 01과 같은 R8로 표시한다. 3열/2열 편집 구조와 네 단계 IA는 유지한다.

## 홈·공간 방향 최신 계약 · 2026-10-07 (우선 적용)

사용자 지정 Figma 홈 `175:272`, 공간 사진 `173:118`, 도면 `182:882`를 기준으로 한다. 홈의 프로젝트 이름·공간 유형은 수정 가능한 기본값이다. 두 값을 그대로 사용하거나 고칠 수 있고, 익명 참가자 번호(P01 형식)까지 세 항목이 유효하면 시작한다. 버튼 앞에 로컬 편집 기록 안내를 표시하며 시작 시 과업 A 기록과 새 프로젝트를 함께 준비한다. 같은 참가자의 진행 중 프로젝트는 이어가고, 홈에서 명시적으로 수정한 이름·유형만 반영한다. 건드리지 않은 기본값으로 저장된 이름을 덮어쓰지 않는다. 별도 설정 화면은 추가하지 않는다. 저장된 프로젝트·다른 공간은 홈의 목록 대화상자에서 계속 사용할 수 있고 로고는 홈으로 이동한다.

새 참가자 프로젝트는 학교 사진 2장·레퍼런스 3장·기본 도면만 준비하며 배치 요소·연결·카메라는 비어 있다. 앞쪽 벽, 뒤쪽 벽, 창문이 있는 벽, 출입문이 있는 벽, 출입문의 5개 표시 그룹과 종속 창 2개는 필수 보존한다. 위치·형태·삭제·잠금 해제는 불가하지만 호환되는 탈착식 장식·벽/천장 조명을 막지 않는다. 기존 프로젝트를 자동으로 다시 잠그지 않는다.

1단계의 디자인 목표는 원하는 결과를 적는 사용자 프롬프트다. 생성 프롬프트·결과 당시 조건·실험 최종 조건에 포함한다. 사진에서 실측 도면을 자동 생성하지 않으며 이 목표를 실제 구조의 근거로 취급하지 않는다. 전체 분위기 이미지는 최대 4장이며 프로젝트 전체 레퍼런스 8장 제한에 포함한다. 네 단계, 배치 20개 제한, 보존·충돌·동선·출입 여유 검사, 서버 60/20회 한도와 결과 이력 계약은 유지한다.

## 조명·진열 상품·시점 편집 보정 · 2026-10-06

레이아웃 조명 도구의 기본 설치는 스탠드형 바닥 조명이다. 벽·천장 설치 선택과 각 설치 방식의 안내를 유지한다. 위치가 지정된 천장 조명은 바닥 가구와 별도 층에서 검사하고, 같은 천장 영역의 다른 위치를 허용한다. 기존 등기구 및 같은 천장 위치의 충돌은 막는다. 진열 상품은 적용 중인 전시대·가구를 도면에서 누르거나 오른쪽 목록에서 선택해 연결한다. 받침이 없거나 위치가 없으면 먼저 배치하도록 안내하며 바닥에 직접 놓지 않는다. 시점 수정의 이전 단계는 4단계 생성 전 확인이다.

## 주석 기반 화면·알림 정리 · 2026-10-01 (우선 적용)

레이아웃 왼쪽은 도구 목록, 오른쪽은 그리기 설정 또는 선택 요소 속성을 보여 준다. 분위기 영역은 같은 조명·색·소재를 적용할 범위, 통행 동선은 비워 둘 이동 공간으로 짧게 설명한다. 범례는 도면 너비의 접힌 버튼을 누르면 전체 기호를 펼치며 가로 스크롤을 사용하지 않는다.

레퍼런스 이미지는 3열·최대 3행 미리보기이며 더 많은 과거 자료는 전체 보기 대화상자로 확인한다. 일반 참고 사진은 바로 업로드하고, 상품 자체 사진을 등록할 때만 용도를 선택한다. 적용 버튼은 패널 아래에 고정하고 실제 이미지/선택 영역 드래그는 선택적 보조 조작으로 제공한다. 매핑 현황의 변경은 같은 탭에서 형태·조명·색·소재의 가져올 내용만 바꾼다. 이 화면에서 배치 요소의 위치를 조정해도 출처·선택 영역·연결은 유지하며 기존 보존·충돌·대상 검사를 적용한다.

시점 요약의 모든 시점은 카메라 아이콘과 목적 설명을 함께 사용한다. 배치 좌표 목록 대신 도면을 확인한다. 저장한 결과가 없을 때 결과 확인·수정 버튼은 비활성이다. 모든 일시 알림은 2초 뒤 사라지고 X로 즉시 닫을 수 있다. 알림 닫기는 저장 상태·검사 조건·삭제 복구 기록을 버리지 않는다. 사용자의 결정을 기다리는 삭제/보존 확인은 알림이 아닌 입력 폼이며 X로 취소한다. 자료 불러오기 실패와 생성 조건 문제는 해당 자료/항목의 상태로도 남긴다.

## 최종 UT 화면 정리 · 2026-10-01 (아래의 이전 설명보다 우선)

상위 IA는 공간·방향 설정 → 레이아웃 구성 → 레퍼런스 적용 → 시안 생성의 네 단계다. 레이아웃 도구는 구조/영역/배치 요소를 한 패널에 보여 주며 신규 영역 도구는 분위기 영역(spatial)·통행 동선(passage)만 제공한다. floor/ceiling은 배치 검사와 구형 데이터에 남긴다. 업로드 도면의 실내 윤곽은 1단계에서 사용자가 직접 표시하며 바닥·천장 기본 범위에 함께 반영한다. 구조 자동 추출·실측은 하지 않는다.

배치 요소는 프로젝트당 20개, 등록 레퍼런스 이미지 ID는 컨셉·제품을 합해 8장이다. 영역/구조/전체 공간 조건/표면 매핑 조건은 배치 개수에서 제외한다. 사용자에게 추가한 기본 진열대는 배치 물체이므로 포함한다. 동일 출처의 반복 연결은 이미지 개수를 늘리지 않는다. 과거 초과 데이터는 삭제하지 않으며 새 추가만 막고 편집·삭제·복구를 허용한다. 제한값은 domain/prototypeConfig에 정의한다.

4단계의 기본 진입은 생성 전 확인이며, 신규 프로젝트는 전체 배치·입구에서 안쪽·다른 방향의 추천 시점을 준비한다. 시점 수정은 선택 사항이고 기존 URL·수동 시점·결과 이력은 유지한다. 유효 관람 후보가 부족하면 잘못된 위치를 만들어 세 개를 강제로 채우지 않는다. 추천은 2D 개략 판단이며 정확한 시공·시야를 보장하지 않는다.

## 레이아웃 우선 네 단계 · 2026-10-01

화면의 최상위 단계는 **01 공간·방향 설정 → 02 레이아웃 구성 → 03 레퍼런스 적용 → 04 시안 생성**이다. 최신 사용자 요청에 따라 기존 참고 이미지 우선 순서를 대체한다. 공간 사진·도면·보존·선택적 전체 컨셉은 1단계, 구조·영역·참고 이미지 없는 배치는 2단계, 이미지 전체/영역을 기존 배치에 연결하는 조작은 3단계, 시점·검토·생성·결과·부분 수정은 4단계에 속한다. 기존 URL·저장·과거 결과·유효성 검사·사용량 보호·실험 기록을 보존한다. 이전의 상세 단계 목록은 내부 기능 명세이며 별도의 상위 단계가 아니다.

새 레이아웃은 자동 이름을 사용하고 이름 변경은 선택 사항이다. 기존 배치 없이 이미지 파생 요소를 새로 작성하는 과정을 기본 흐름에서 요구하지 않는다. 동일 이미지 영역을 호환되는 여러 대상에 원자적으로 연결한다. 방 전체를 복제하지 않고 선택한 대상의 형태·조명·색·소재만 연결한다. 연구 목적의 결과 예측·만족도·인지된 효율성·통제감 평가 범위와 기존 학교 졸업전시 기본 시나리오는 유지한다.


## What it is
A desktop-first spatial concept design web app for visualizing renovation/retail/pop-up/exhibition/showroom scenarios. Users specify what must remain in an existing space, select whole-image ambience or concrete elements from multiple references, anchor each element at a compatible location on a floor plan, choose a camera viewpoint and request AI concept imagery. A generated result is compared with the saved constraints; users revise only the needed constraints.

## Target and sample case
Design students and beginning–intermediate users of image generation who can understand photos/plan diagrams but should not need lengthy prompt engineering. Default sample project: AURA POP-UP, a small rectangular cosmetics pop-up space. Its registered original shell walls, window, column, entrance and other permanent structures start with preservation enabled; users can explicitly release and re-enable their locks to correct the plan or revise proposed conditions; the north-side wall/window, column and entrance are especially prominent in the visual review. Apply reference A curved freestanding display at center floor, reference B warm indirect lighting atmosphere to the whole room, reference C removable photo-zone graphic to rear wall. Reference B is a proposed ambience condition, not a claim that the room already has a movable ceiling fixture. View from entrance toward center.

## Screen inventory
1. Project list/new project and space source import.
2. Space setup showing existing-space photographs and floor plan as distinct surfaces. The plan identifies whether it is an uploaded image, a manually started schematic, or a prepared sample. None is inferred from the photographs; uploaded images do not automatically extract walls or dimensions. This screen explains that the plan is the 2D basis for Keep, element placement and viewpoints. Structure is marked by drawing a point or segment on the visible plan; floor, ceiling, spatial and circulation areas are marked by dragging a rectangle or tracing an outline or tracing an outline on that same plan. Switching tools never replaces the plan with a coordinate-only form; numeric entry remains an accessible alternative. Multiple photographs center the active frame, show a sliver of each available neighbor, and offer current/total count, previous/next controls and drag navigation; their lower scroll bar is hidden.
3. Keep editor with linked photo/plan highlights and a selected-item explanation. Every registered structure has an accessible “필수 보존 (위치 고정)” on/off switch. While on, its geometry and deletion are locked; off allows validated plan correction and placement editing. Structural origin is independent of that switch. Connected locked openings must be released before moving their parent wall; unlocked openings slide along their wall. The switch is not a claim that a physical wall or pillar can be relocated in reality. Photo markers are approximate correspondence only, never measured geometry.
4. Reference library and applied/excluded element extraction. The selected image has a visible delete action with linked-element count, explicit cancel/confirm and persistent undo. Deleting a reference removes its current derived elements; removing one element retains its source. Historical images and their saved reference attribution remain available, marked stale. Each element links back to its original reference. Saved apply/exclude and appearance/material conditions and type read as text in References and Placement; “조건 편집” opens drafts in References, with explicit save/cancel. Image-wide atmosphere is not a freestanding object. Product, element and atmosphere images have role-specific guidance.
5. Spatial staging board: left applied-element and structure list, large central plan canvas, right contextual property inspector. Explicit selection distinguishes a structure edit from a design-element placement. Released structures support drag, keyboard or numeric adjustment with live selection feedback. Excluded elements stay in References and Review. The plan overlays all usable floor areas, permanent structures and movable elements as separate synchronized layers; selecting an element in the list and changing it in the inspector or canvas updates the same placement. Keep preserves the wall itself. Compatible removable graphics/lights attach without repeated confirmation; wall replacement and physical opening/clearance conflicts remain blocked. Camera markers are hidden here to keep the placement task focused. Side panels may be hidden independently to enlarge the canvas.
6. Viewpoint editor: one primary camera; additional cameras optional through one camera-list action. The camera is recognizable as a camera marker; dragging its body changes position, while a separate, visibly labeled rotation handle changes heading. Empty-plan clicks do not move it. A property inspector remains beside the same canvas on desktop; on narrower widths the plan comes first and the list and inspector follow. Structure, area and passage editing live in controls adjacent to the plan rather than in a distant page section. Summary before generation. The Review step distinguishes the AI image action from the preloaded sample. Use one short sentence to explain one image per selected view and its generation-count deduction; disclose transmitted inputs and result limitations in an optional detail group. ## Feedback and action clarity
Space setup uses clearly named structure tools and area purposes with direct drawing guidance. A host wall is identified by name and highlight on the actual plan, with snapping for window/door/entrance gestures. Selecting/moving shows which partitions really can move and says when none exists. Prevent duplicate markings and same-layer physical object overlap without forbidding legitimate floor, ceiling and ambience layering; failed drawings leave the saved plan intact.

Short informational and success notices begin fading after three seconds and retain immediate manual dismissal. Blocking validation or other messages that a user must read remain visible until dismissed or resolved. “새 미리보기 열기” acts on the current conditions; “결과 이력 보기” navigates to previously saved results. The two actions must not appear as duplicate controls for the same destination. A preflight synthesis explains which preserved structures, applied/excluded elements and viewpoint define the proposed concept; it is a summary of user settings, not a prediction or generated image.

## Demo and generation boundary
The app completes the offline interaction flow with preloaded coherent sample photos/plan and informative sample result(s). The app clearly labels demonstration imagery. When a configured server-side OpenAI provider is available, a separate explicit action creates one image per selected camera in a sequential batch from the saved conditions and supported reference images. When several existing-space photos are registered, the user chooses which one photo anchors this paid request; the sample preview remains a fixed example. A whole-image reference sends its full image, whereas references with only selected regions send a crop or a combined image of up to four distinct regions from the same source. More than four such regions blocks the request before the paid call. It sends those inputs only after the user chooses that action; the server reads the API key from its environment and enforces a durable shared generation quota; the user supplies no key, code or invitation link. The private quota counts reservations before the provider call: 60 per Korean calendar day across all browsers and 20 per signed anonymous browser per Korean calendar day, one active request across users/instances, and persistent request-ID replay protection. Storage failure blocks paid calls; uncertain calls are never refunded. A missing or expired key leaves the sample workflow available. Results record whether the image came from AI or the sample and preserve the exact condition snapshot, including the selected existing photo for AI results. An image model may fail to follow Keep, dimensions, wall placements or other physical constraints, so the app requires user review rather than asserting spatial accuracy or cross-view consistency. Keep operator pricing guidance in API_INTEGRATION.md instead of the participant interface. Label the image action “AI 이미지 생성” and read-only refresh “생성 가능 여부 확인”; refresh checks availability and shared quota, never image progress or the model itself. If a sent request's outcome cannot be confirmed, retain a visible cost warning and block another request for at least 180 seconds; reopening the paid action requires an explicit acknowledgement after that wait.

## User-directed plan, references and generation reconciliation · 2026-09-29
Uploaded image dimensions and aspect ratio define the canvas. Fresh upload starts with no old sample rectangle or inferred walls; clear current geometry anchors with explicit undo, preserving old result snapshots. The user can explicitly retain annotations for alignment instead. Offer landscape/portrait schematic starters and a blank manual outline. Trace polygon vertices on the visible plan; curves use multiple points as an approximation. Floor footprints and viewpoints must fit the actual outline, including concave cutouts. Released walls can be aligned horizontally/vertically and point structures can use rect/circle sizes. No automatic structural extraction, measured accuracy, CAD or 3D is claimed.

The References panel shows only the focused source's elements. Its title stays pinned; the selected element appears first. Applied reference sources have no count cap. Above three sources, pack all sources into up to three contact sheets with source/crop manifests; this never creates an extra model request. Input size and prompt bounds remain technical limits, and dense sheets reduce detail. Display products require a chosen applied fixture/furniture support or an explicit basic support added by the user. Product/support overlap is intentional; moving the support carries its products. Other elements have floor/wall/ceiling/area categories so their anchors remain typed.

Camera, fixture and product geometry have distinguishable markers without a new icon library. Structure names are packed to avoid label collisions; a lock badge toggles preservation. Canvas errors overlay without resizing it. Undo/redo (Ctrl+Z / Ctrl+Shift+Z) keeps up to 50 edit states per project in the current tab; deletion undo remains persistent. Deleting a camera retains its result snapshots and makes the first remaining camera primary when needed; deleting all cameras blocks generation until one is added.

Review permits choosing several cameras. One action queues one image request/reservation per chosen camera, disables repeated generation for the entire batch and saves each result separately. On a later failure, keep earlier images and stop the batch. The shared daily cap is 60 and the anonymous-browser daily cap is 20; both reset at Korean midnight from server time, not from deployment. Status is read-only and refreshes at midnight while Review remains open. Browser identity is a signed HttpOnly cookie, not a login/account or a reliable cross-device person identifier. Clearing cookies or using another browser establishes another identity; the shared cap still applies.

## 적용 범위 연결과 영역 가시성 · 2026-09-29
참고 이미지의 참조 범위(전체 이미지/잘라낸 부분)와 요소를 적용할 공간 범위는 별개다. 요소 등록 때 또는 선택한 요소의 배치 속성에서 실제 이름으로 위치를 연결한다. 조명 분위기·색·기타 공간 연출은 전체 공간 또는 저장한 공간/바닥 영역을 선택한다. 두 레퍼런스의 조명 조건은 각각 전체 공간과 특정 영역에 독립적으로 연결할 수 있다. 천장 등기구는 천장 영역, 벽 조명은 벽 구간, 스탠드 조명은 바닥 위치를 사용한다. 비어 있는 바닥 영역은 진열대 등의 선택적 배치 대안이며 기존 바닥 점을 미지정으로 표시하지 않는다.
아직 그리지 않은 영역은 사용자가 ‘도면에서 영역 추가’를 눌러 그릴 수 있다. 저장 후 그리기 도구를 유지하며 직접 원하는 단계로 돌아간다. 영역 연결은 공통 조건 변경이며 기존 결과를 이전 조건으로 보존한다. 선택하지 않은 적용 위치를 자동으로 전체 공간으로 바꾸지 않는다.
공간 준비와 배치 도면은 영역 종류별 표시, 선택 영역 강조, 다른 영역 옅게 표시, 이름표 전체 표시 옵션과 실제 이름 목록을 제공한다. 기본은 선택한 영역의 이름만 표시하고 다른 범위는 채움 없이 경계 패턴으로 구분한다. 전체 공간/지정 영역 연출의 개별 범위 표시도 현재 선택한 요소만 강조한다. 물리적 진열대는 계속 표시한다. 표시 옵션은 도면·연결을 삭제하거나 바꾸지 않으며 새로고침 시 기본 보기로 돌아간다.

## 이동 제한 범위 가시성 · 2026-09-29
공간 준비·유지할 요소·배치·시점의 도면에서 등록된 통행 동선과 출입/문 여닫이 여유 공간을 빗금으로 표시한다. 이 범위는 분위기 영역 표시 설정과 분리하여 항상 보인다. 실제 바닥 경계와 물리 배치 요소의 검증용 점유 윤곽도 표시하며, 구조/요소 레이어를 숨겨도 충돌에 필요한 최소 윤곽을 남긴다. 흰 바닥 전체가 모든 요소에 유효한 위치라는 뜻은 아니다. Keep 보존 의미와 유형별 배치 검사는 그대로 유지한다. 카메라는 동선/여닫이 영역에 놓을 수 있다. 기둥/가벽 편집에서 기존 카메라 위치가 실제 제한인 경우에만 읽기 전용 카메라 아이콘을 보이며 시점 편집 조작을 제공하지 않는다.

## 도면 가시성과 이미지 생성 입력 · 2026-09-29
- 일상 캔버스에서는 실제 벽·기둥·물체 윤곽을 우선한다. 천장·분위기 영역은 기본 숨김이며 선택하면 표시한다. 동선과 여닫이 제한은 항상 표시한다. 표시 변경은 저장 조건/수정 버전을 바꾸지 않는다.
- 모든 실제 생성 요청은 기존 공간 사진, 저장한 구조·배치·선택 카메라의 도면 가이드 이미지, 적용 레퍼런스를 전달한다. 업로드 도면은 가이드의 배경으로 보존한다. 개략 도면은 직접 지정한 형상을 렌더링하며 사진 분석/실측/3D 재구성이 아니다.
- 조명 요소는 빛의 온도·방향·퍼짐만 적용한다. 색상/마감 요소를 별도로 지정하지 않았다면 기존 벽/바닥의 중립색 재질을 유지하도록 요청한다. 실제 이미지의 완전한 도면 일치를 보장하지 않는다.
- 시안의 ‘저장된 배치 도면과 비교’는 해당 결과의 조건 스냅샷을 사용한다. 과거/샘플 이미지에도 배치 기록을 보여줄 수 있지만, 가이드가 과거 모델 입력으로 사용되었다고 주장하지 않는다.


## 실제 공간 사진과 요소 가시성 · 2026-10-01
- 새 프로젝트의 공간 사진 업로드는 평면도·구조·배치·시점을 자동 생성하지 않는다. 사용자는 평면도를 별도로 올리거나 실측하지 않은 개략 도면을 직접 작성한다. 학교 예시의 도면도 사전 준비한 개략 배치다.
- 생성은 원본 공간 사진을 건축적 외관 기준으로, 저장 도면을 2D 위치 기준으로 사용한다. 보존 조건이나 제안 배치에 없는 이동식 책상·의자·잡동사니는 비운 상태를 가정하고 제안 요소를 설치한다. 고정 구조와 명시적으로 보존한 물체는 유지한다. 이 과정은 시안 1장 생성의 조건이며 별도 빈 공간 생성 호출이나 원본 사진 변경이 아니다.
- 배치 물체 수와 공간·표면 연출 조건 수를 구분한다. 미배치·적용 제외·연결 위치 누락 요소는 보존하고 목록에서 이유를 표시한다. 20개 제한의 계산 규칙은 변경하지 않는다.
