# 여러 시점 연속 생성 수정·검증 · 2026-09-29

## 확인한 원인과 변경

서버가 생성 이미지 응답을 종료한 뒤 `finally`에서 비공개 quota의 active lease를 해제했다. 브라우저는 응답을 받자마자 다음 카메라를 요청하므로 완료 쓰기가 지연되면 이전 잠금 때문에 다음 요청이 거절될 수 있다. 완료 쓰기를 보류한 단위 테스트에서 수정 전 이미지 응답이 먼저 전달되는 현상을 실제로 재현했다. 사용자의 과거 요청이 반환한 정확한 오류 코드를 서버 로그로 확인했다고 주장하지 않는다.

- 정상 완료는 잠금 해제 후 응답한다. 오류 응답도 같은 완료 순서를 따른다.
- 완료 CAS 실패를 성공으로 간주하지 않는다. 저장소 장애·지연 시 이미 받은 이미지와 예약을 보존한다. 완료 대기는 최대 8초/함수의 남은 시간 안으로 제한하고 모델 제한 시간에도 정리·응답 여유를 남긴다.
- 다음 시점 전에는 읽기 전용 상태 조회로 준비 여부를 확인한다. 처리 중 상태는 2초 간격, 최대 20초 대기한다. 각 GET은 최대 8초 또는 남은 대기 시간 이내다.
- 완료 수와 다음 시점 이름을 표시한다. 중복 클릭/시점 변경은 전체 배치가 끝날 때까지 잠근다. 유료 POST를 자동 재시도하지 않는다.
- 한도 소진·상태 조회 실패·대기 초과·후속 생성 오류는 완성 이미지를 보관하고 나머지만 중단한다. 프로젝트 기록 저장 실패에 성공 알림이 함께 나오던 분기도 수정했다.

## 실제 실행 결과

| 검증 | 결과 |
| --- | --- |
| ESLint | 통과 |
| 클라이언트 TypeScript + API NodeNext / Vite build | 통과 |
| Vitest | 19개 파일, 160개 테스트 통과 |
| 다중 시점 대기·실패 브라우저 QA | 7개 항목 통과 |
| 기존 시점 삭제·되돌리기·배치·참고 이미지·반응형 회귀 | 14개 항목 통과 |
| 클라이언트 비밀 값 / 폰트 바이너리 검사 | 일치 0건 / 포함 0개 |
| 모의 브라우저 페이지 오류 | 0건 |
| 실제 유료 모델 요청 | 0회 |

API 테스트는 실제 `GenerationQuota`와 메모리 CAS 저장소를 사용해 첫 응답 수신 즉시 두 번째 카메라 요청을 시작한다. 두 요청이 각각 한 번 성공하고 두 예약이 남으며 잠금이 해제되었다. 완료된 UUID 재전송은 409이며 모델 대역은 다시 호출되지 않았다. 지연/장애 테스트에서도 받은 이미지 응답은 유지되며 횟수를 반환하지 않았다.

브라우저에서는 첫 이미지 저장 후 처리 중 GET을 보류하고 추가 유료 POST가 없는지 확인했다. 처리 중 응답 두 번 이후 준비 응답으로 전환하자 두 번째·세 번째가 순서대로 실행되었다. 고유 UUID 3개, 서로 다른 카메라 3개, IndexedDB 이미지 자산 3개, 두 일일 한도의 정확한 3회 차감을 확인했다. 대기 화면의 캡처도 직접 확인했다.

상태 한도 소진/503/20초 동안 계속 처리 중인 경우에는 POST가 첫 요청 하나에 그쳤다. 첫 이미지와 중단 사유가 보였다. 두 번째 POST의 연결 실패에서는 첫 이미지를 보존하고 세 번째 호출 및 즉시 재시도를 막았다. 기존 회귀에서는 1440/1070/390px의 7단계 뷰포트와 시점 삭제·되돌리기·벽 전환·참고 이미지 삭제를 확인했다.

## 검증 범위

QA는 분리된 브라우저 저장 컨텍스트와 모의 이미지/상태 응답을 사용한다. 실제 OpenAI 호출, 이미지 품질, 계정 결제/조직 권한을 검증한 결과가 아니다. 실제 quota를 초기화하거나 예약을 삭제하지 않았다. Vite의 500KB 청크 권고 경고는 남지만 빌드는 성공했다.
