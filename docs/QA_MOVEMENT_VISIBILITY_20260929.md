# 이동 제한 범위 가시성 검증 · 2026-09-29

## 변경 범위

- 공간 준비·유지할 요소·배치·시점에 등록된 동선/문 여유 공간 빗금과 바닥/실제 물체 점유 윤곽을 표시한다.
- 구조·요소 표시를 꺼도 최소 제약 윤곽은 남긴다. 동선은 항상 표시하며 표시 설정이 조건을 변경하지 않는다.
- 드래그/회전 후보에 기존 저장 검증을 실행한다. 불가한 후보는 놓기 전에 이유를 보여주고 저장 위치를 보존한다. Keep/시점에도 도면 안의 닫을 수 있는 거절 안내를 연결한다.
- 관련 기둥/가벽 편집에서 기존 카메라 장애 위치만 읽기 전용으로 표시한다. 카메라는 동선에 놓을 수 있다.
- 이름표가 실제 동선·여유 공간·물체·기둥·카메라 표시를 덮지 않도록 고정 영역을 예약하고 연결선을 그린다. 공간이 부족하면 이름을 접어도 실제 범위는 남긴다. 접힘 안내는 상시 설명이므로 이름 수 변경이 캔버스 높이를 바꾸지 않는다.

직접 포인터를 사용하여 보존을 해제한 기둥/진열대의 동선 충돌, 정상 기둥 이동, 동선 위 카메라 이동과 기둥 충돌을 검사했다. 미리보기 중 저장 데이터가 바뀌지 않고 거절 후 위치/캔버스 bounds가 동일하며 정상 놓기에서만 저장되었다. 오류 overlay는 absolute이며 닫기와 정상 저장으로 해제된다.

1440×900, 1280×800, 1113×697, 768×900, 390×844의 7개 단계에 바깥 페이지 스크롤이 없었다. 이동 가시성은 별도로 1070×671/390×671의 4개 캔버스를 검사했다. 작은 Keep 화면에서 이름표가 실제 보호 범위를 덮지 않는 bounds 검사도 통과했다. 데스크톱/1070/390px 캡처를 직접 확인했다.

QA 브라우저는 별도 로컬 저장 컨텍스트를 사용했다. 실제 이미지 요청은 가로채거나 모의 응답으로 검증했으며 실제 유료 모델 호출은 **0회**다. 이 결과는 이미지 생성 품질이나 실제 시공 가능성 검증이 아니다. 기존 quota/API 동작, 저장 스키마와 실험 기록 범위를 확대하지 않았다.

## 확인 중 발견하여 수정한 회귀

- 원래 구조 표시를 끈 상태에서 이름표 공간까지 예약해 숨긴 물체 이름이 접히던 문제를 수정했다.
- 동선 이름에 긴 접미사를 붙여 이름표 밖으로 글씨가 나가는 문제를 실제 이름과 빗금 설명으로 분리했다.
- 작은 화면의 이름표가 실제 동선 빗금을 덮던 문제를 고정 범위 예약으로 수정했다.
- 카메라 수가 늘어 이름표 접힘 안내가 생기면 캔버스 높이가 달라지던 문제를 상시 설명으로 수정하고 뷰포트 회귀를 재실행했다.

## 제한

표시는 사용자가 등록한 계획 데이터와 기존 보수적 점유 검사에 근거한다. 모든 흰 바닥이 모든 요소에 유효하다고 표시하지 않는다. 많은 이름은 접힐 수 있으며 실제 전체 이름과 편집 값은 목록/속성에서 확인한다. Vite의 500KB 청크 권고 경고는 남지만 빌드는 성공했다.

그리기 도구를 쓰는 동안 표시 이름표도 읽기 전용 pointer-events none으로 전환한다. 상시 동선 이름표가 그리기 시작 지점을 가로채지 않는지 별도 확인한다.
