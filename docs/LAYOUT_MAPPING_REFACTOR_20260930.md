# 레이아웃 먼저 구성하는 4단계 개편

## 수정 전 분석

| 기존 화면/URL | 새 단계 | 유지할 동작 |
|---|---|---|
| space / keep | 01 공간·방향 설정 | 실제 사진, 도면 업로드, 개략도, 기존 구조 보존 |
| placement / space의 그리기 | 02 레이아웃 구성 | 구조·영역 그리기, 배치·회전·크기, 충돌 검사, 실행 취소 |
| references | 03 레퍼런스 적용 | 이미지 업로드·영역 선택·삭제 복구, 기존 요소에 연결 |
| camera / review / results | 04 시안 생성 | 시점 편집, 조건 검토, 생성·배치 수정·이력·내보내기 |

기존 `DesignElement.sourceReferenceId`와 생성 전 검증, 이미지 입력 묶음, 조건 기록이 참고 이미지에서 요소를 먼저 만드는 순서에 묶여 있다. App의 참고 이미지 화면은 이미지·요소 등록·배치 이동을 각각 요구한다. 기존 왼쪽 단계 목록은 작업 도구 패널과 중복된다. 도면의 기본 이름표와 같은 사각형 표시는 시각적 구별을 어렵게 한다.

## 호환 계획

저장소 봉투/Project의 schemaVersion 1은 유지한다. `layoutVersion: 2`와 `referenceBindings`를 선택 필드로 추가한다. 기존 elements를 지우지 않고, 독립된 레이아웃 요소에 필요한 layoutKind/locked를 보완한다. 새 요소는 참고 이미지 없이 먼저 생성할 수 있으며 `origin: layout`, 빈 sourceReferenceId를 명시한다. 연결은 별도의 ReferenceBinding으로 관리하고 기존 생성·도면·로그 소비자를 위한 sourceReferenceId/sourceRegion 투영도 같은 원자적 변경에서 갱신한다. 중복된 위치 데이터 배열은 만들지 않는다.

이전 프로젝트의 요소 ID·위치·배제 조건을 유지하여 연결을 일회성으로 복원한다. 기존 결과의 snapshot은 변경하지 않는다. 참고 이미지 삭제 시 새 레이아웃 요소는 남기고 연결만 제거한다. 이전 형식의 이미지 파생 요소 삭제 동작은 호환 경로에 유지한다. 연결/해제는 공통 수정으로 기록하여 이전 결과를 오래됨으로 표시한다. 배치·참고 이미지·생성은 기존 validation과 quota를 사용한다.

## 변경한 파일과 이유

- domain/types, layoutMapping, revisions, validation: 독립 레이아웃/연결 및 보존 검사
- services/persistence, generationContract: 추가 필드 검증과 참고 이미지 없는 레이아웃의 생성 설명
- app/workflow, App: 4단계 상단 진행 표시와 작업 연결
- components/LayoutWorkspace, MappingWorkspace, PlanCanvas, LayoutSymbol: 도구·다중 선택·드롭·기호·카메라 표시
- styles/layout-mapping: 기존 의미 토큰을 쓰는 2/3열 화면
- tests와 제품/상호작용/QA 문서: 호환·드롭·실행 취소·상태 유지 확인

유료 이미지 호출, 사용량 원장 초기화, 지도·계정·3D·제품 추천 기능을 이 개편 과정에서 추가하지 않는다.

## 완료한 IA와 데이터 변경 · 2026-10-01

상단 4단계만 유지한다. 1단계의 사진/도면과 정보 패널, 2단계의 도구/캔버스/선택 속성, 3단계의 이미지·매핑 목록/캔버스, 4단계의 시점·검토·결과 내부 상태를 구현했다. 기존 브랜드·공식 UI 아이콘·보존·검증·생성·로그를 사용한다. 전시대·테이블·의자·조명을 참고 이미지 없이 추가하고, 이름은 자동 구분한다. 건축 기호와 윗면 도형은 범례에 대응하며 이름은 선택/마우스 올림 때 보인다.

ReferenceBinding은 기존 위치 데이터와 분리되어 한 이미지 영역을 여러 요소에 연결한다. 썸네일/선택 영역 드롭, 클릭·적용, Shift 선택/마우스 다중 선택, 연결 변경/해제를 지원한다. 하나라도 잘못된 대상이면 전체 변경을 거절한다. 벽/영역/전체 공간 연결과 가벽 A/B 면을 유지한다. 이미지 삭제·연결 해제는 배치를 지우지 않는다. 새 필드는 이전 기록에 자동 강제 덮어쓰기를 하지 않으며 다음 실제 수정 저장 때 함께 저장한다. 과거 결과는 보완하지 않고 원본 snapshot을 보관한다.

추가 변경 파일:

- `src/services/experiment.ts`: 새 시작/종료 조건의 workflow_version/reference_bindings 및 다중 연결 수 기록. 이전 세션·ZIP 형식 보존.
- `src/styles/tokens.css`: 기존 글자 크기 스케일을 의미 변수로 묶고 낮은 편집 창의 제목 변형을 정의.
- `scripts/build-guides.py`, `docs/USER_GUIDE.md`, `public/guide/`: 새 실제 조작 순서로 참여 가이드 HTML/PDF 갱신.
- `docs/EXPERIMENT_RUNBOOK_AND_VIDEO.md`, `docs/SCENE_EDIT_VIDEO_FLOW.md`, `output/pdf/`: 연구자 문서와 영상 구성 순서를 갱신. 진행자 PDF는 공개 가이드에 포함하지 않음.
- 제품·디자인·상호작용·구조·QA·로그·변경 기록 문서: 새로운 흐름과 호환 범위를 일치시킴.

## 검증 결과

자동 검사: 24개 파일의 193개 테스트 통과. lint와 프론트/서버 TypeScript 빌드 통과. 기존 일일 공용/익명 한도, 불확실 응답, 순차 시점 생성, 입력 영역, 보존·물리 충돌 검사를 포함한다.

승인된 격리 브라우저에서 학교 공간 → 전시대 4개·테이블·의자·조명·영역 → 이미지 영역을 전시대 1·2·4에 한 번에 연결 → 드롭으로 다른 전시대 적용 → 벽/전체 조명 연결 → 시점 → 검토 → 결과 및 부분 수정을 수행했다. 새로고침·Back/Forward·연결 해제·Ctrl+Z/다시 실행·그룹 변경·새 요청의 원본 조건 저장·실험 기록을 확인했다. 1070×671 / 1280×720 / 1600×900에서 문서 외부 스크롤 및 브라우저 JavaScript 오류가 없었다.

추가 브라우저 회귀: 가벽 그리기 이후 도구 유지, A면 부착/B면 매핑, 참고 이미지 삭제 후 배치 보존·복구, 요소 잠금/해제, 영역 이름·폭 변경, 구형 데이터의 로드/수정 저장, AURA 사전 제공 샘플의 실제 열기·sample 표시를 확인했다. 카메라는 1~3단계에 숨고 시점 편집에만 방향이 보이며 검토/결과에서는 위치만 표시한다. 공개 가이드와 진행자 PDF 전 페이지를 렌더링해 겹침·잘림 없이 확인했다.

이미지 요청·저장·수정 후 stale 표시는 격리된 API 테스트 응답으로 확인했다. 유료 모델을 실제 실행하지 않았으며 이 테스트 이미지를 실제 AI 결과나 배포 샘플로 추가하지 않았다. 새 학교 시나리오의 생성 품질이 검증됐다고 주장하지 않는다.

## 남은 문제와 UT 전 확인

- 재현되는 필수 조작 오류는 최종 QA에서 발견하지 못했다. 브라우저 내장 도구는 환경 오류로 시작되지 않아 사전 승인된 격리 브라우저로 검증했다.
- 빌드에는 기존과 같은 500KB 초과 단일 JS 묶음 경고가 남는다. 실행·저장·생성 검증은 통과했다.
- 논문에서 실제 생성 결과를 평가하기 전에 새 학교 공간 조건으로 실제 모델을 실행하고 도면·부착 면·카메라·색감을 수동 대조해야 한다. 이 개편의 기능 검사만으로 공간 재현 정확도를 보증하지 않는다.
- A/B는 기존 기록 태그이며 완성된 평가 자료·자유 텍스트 비교·서버 실험 로그 수집·정답 코딩을 추가하지 않았다. 비교 실험을 진행할 경우 기존 진행자 문서의 자료/평가 준비가 필요하다.
- 선택 기능을 추가로 제안하지 않는다. 이번 변경 범위는 요청한 레이아웃 우선 작업 흐름과 기존 기능 보존이다.
